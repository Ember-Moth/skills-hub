# Tauri v2 Android Native Plugin

## When to Use

Use this skill when building a **Tauri v2 plugin that runs on Android only or has Android-specific behavior**, especially when:

- Wrapping a native Android library distributed as `.aar`
- The native lib provides its own background service (e.g., VpnService, WorkManager, foreground service)
- The native lib calls back into Java/Kotlin through gomobile-generated bindings (`go.*`, `lib.Seq`)
- Commands need to request Android system permissions at runtime (VPN, camera, location, storage)

Do NOT use this skill for desktop-only Tauri plugins or plugins that just call system APIs without bundling an AAR.

## Required Reading Before Starting

Read these docs to understand the Tauri plugin conventions:

1. https://tauri.app/start/create-project/plugins/ — official plugin overview
2. https://tauri.app/develop/plugins/develop-mobile/ — Android/iOS plugin specifics
3. https://v2.tauri.app/develop/plugins/ — v2 API reference (if using Tauri v2)

The four official structural requirements you must follow:

| File / Directory | Purpose |
|---|---|
| `src/lib.rs` | `pub fn init() -> TauriPlugin<R>` that wires up commands, permissions, lifecycle |
| `src/commands.rs` | `#[command]` async handlers, one per public command |
| `src/models.rs` | Request/Response types with `#[serde(rename_all = "camelCase")]` |
| `src/mobile.rs` + `src/desktop.rs` | Two implementations; mobile bridges to Kotlin/Swift |
| `build.rs` | Lists command names → auto-generates `permissions/autogen.toml` |
| `android/` | Android library with `build.gradle`, AAR in `libs/`, Kotlin source |
| `android/src/main/AndroidManifest.xml` | MUST contain `<service>` for your service |
| `guest-js/index.ts` | TypeScript bindings (one fn per command) |
| `permissions/default.toml` | Lists `allow-<command>` for every command |

The full directory layout, generated by `cargo tauri plugin init`, is the source of truth.

## Critical Pitfalls to Avoid

### 1. Build/Compile Errors

**`gson` not declared but imported**

If you find yourself writing `import com.google.gson.JsonObject`, use `org.json.JSONObject` instead. Android system `org.json` is always available and matches `JSONObject` from `kotlin stdlib`, so no extra dependency is needed.

**Empty `catch` block without `{}`**

```kotlin
try { Thread.sleep(100) } catch (_: InterruptedException)   // ← compiles? no
try { Thread.sleep(100) } catch (_: InterruptedException) {}  // ← correct
```

**`load()` lifecycle method signature**

```kotlin
import android.webkit.WebView          // ← must import the platform type

@TauriPlugin
class ExamplePlugin(...) : Plugin(...) {
    override fun load(webView: WebView)  // ← do NOT use fully-qualified name
}
```

If you write `override fun load(webView: android.webkit.WebView)`, the parameter type differs from the parent class's `load(WebView)` and the lifecycle hook is silently dropped.

**`invoke.getBoolean()` is two-arg, not nullable**

```kotlin
// ❌ compile error: no such method
val x = invoke.getBoolean("key") ?: false

// ✅ correct API
val x = invoke.getBoolean("key", false)
```

**Missing `androidx.activity` dependency**

`registerForActivityResult(...)` requires:
```gradle
implementation "androidx.activity:activity-ktx:1.9.0"
```

**`as ComponentActivity` cast**

```kotlin
(activity as androidx.activity.ComponentActivity)
    .registerForActivityResult(...)  // ← ClassCastException if host Activity isn't a ComponentActivity
```

Document the host Activity type requirement, or use `context.findActivity()` extension + null-check.

### 2. Runtime Crashes

**Missing foreground notification**

Android 8+ kills any Service that doesn't call `startForeground()` within ~5 seconds. A `VpnService` is a Service. You must:

```kotlin
override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
    startForeground(NOTIF_ID, buildNotification(session))
    // ... rest of start logic
    return START_STICKY
}

private fun ensureNotificationChannel() {
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
        val nm = getSystemService(NOTIFICATION_SERVICE) as NotificationManager
        if (nm.getNotificationChannel(NOTIF_CHANNEL) == null) {
            nm.createNotificationChannel(
                NotificationChannel(CHANNEL_ID, "MyService", NotificationManager.IMPORTANCE_LOW)
                    .also { it.setSound(null, null) }
            )
        }
    }
}

private fun buildNotification(title: String): Notification {
    val builder = if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O)
        Notification.Builder(this, NOTIF_CHANNEL)
    else @Suppress("DEPRECATION") Notification.Builder(this)
    return builder.setSmallIcon(android.R.drawable.ic_dialog_info)
        .setContentTitle(title).setOngoing(true).build()
}
```

**Use `startForegroundService` on Android 8+**

```kotlin
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
    ctx.startForegroundService(intent)
} else {
    ctx.startService(intent)
}
```

**Race between `serviceInstance` and `coreController`**

`XrayPlugin.kt` keeps `XrayVpnService.serviceInstance` and reads `coreController` from it. Both can become null between the null-check and the use if the user issues `stopCore` concurrently. Always copy into a local `val`:

```kotlin
val ctrl = XrayVpnService.serviceInstance?.coreController
    ?: run { invoke.reject("core not started"); return }
// ctrl is a local reference now, safe to use
```

**`@Volatile` on cross-thread mutable state**

`pendingStart` is written by the main thread and read by the ActivityResultLauncher callback. Without `@Volatile` you risk a torn read on ARM:

```kotlin
@Volatile
private var pendingStart: PendingStart? = null
```

**`stopForeground(true)` must come before `stopSelf()`**

If you `stopSelf()` then `stopForeground`, the notification stays stuck in the status bar for seconds. Reverse order.

### 3. Permission Errors

**Every plugin command is deny-by-default in Tauri v2**

If `permissions/default.toml` does not list `allow-<command>`, the JS side gets "denied" error even though the command is wired. Always include a default.toml with every `allow-<command>`:

```toml
"$schema" = "schemas/schema.json"

[default]
description = "Default permissions."
permissions = [
  "allow-start-core",
  "allow-stop-core",
  # ... one per command
]
```

The match between `build.rs` COMMANDS list, `mobile.rs::run_mobile_plugin` strings, and Kotlin `@Command` functions MUST be exact. A single typo breaks the whole chain silently — the Kotlin `invoke.resolve` runs but the JS call gets "command not found".

### 4. native lib (gomobile) Integration

**The `go.*` package must be on the classpath, even if it appears "unused"**

`go.Seq` is the gomobile bridge. Without it, `ClassNotFoundException` at first method call. The AAR includes the `go` classes automatically; do not strip them with R8 unless you know exactly what to keep.

**`Seq.setContext()` lifecycle is subtle**

`Seq.setContext(Context)` is a global static. Two traps:

1. **Set it to a Context that can call `protect()`** (i.e., a `VpnService` instance, not a generic `applicationContext`) — otherwise socket protection silently fails and outbound traffic loops.
2. **Reset it after the service stops** so a stale reference doesn't outlive its owner:

```kotlin
override fun onCreate() {
    super.onCreate()
    Seq.setContext(this)               // VpnService instance, for protect()
    serviceInstance = this
}

fun stopAllService() {
    isRunning = false
    // ... unregisterCallbacks ...
    coreController?.stopLoop()
    coreController = null
    Seq.setContext(applicationContext)  // reset, or just clear on destroy
    stopForeground(true)
    stopSelf()
}
```

**Register Android-Q-specific process finder**

If your underlying engine supports per-process routing via UID (xray-core does), wire up `ProcessFinder`:

```kotlin
import android.os.SystemClock                  // unused, remove
import android.system.OsConstants              // IPPROTO_TCP / IPPROTO_UDP

import androidx.annotation.RequiresApi
import android.net.ConnectivityManager
import java.net.InetSocketAddress

if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q) {
    ctrl.registerProcessFinder(XrayProcessFinder(this))
}

@RequiresApi(Build.VERSION_CODES.Q)
private class XrayProcessFinder(private val ctx: Context) : ProcessFinder {
    private val cm = ctx.getSystemService(ConnectivityManager::class.java)
    override fun findProcessByConnection(
        network: String, srcIP: String, srcPort: Long,
        destIP: String, destPort: Long,
    ): Long {
        if (cm == null || destIP.isBlank() || destPort == 0L) return -1L
        val proto = when (network) {
            "tcp" -> OsConstants.IPPROTO_TCP
            "udp" -> OsConstants.IPPROTO_UDP
            else  -> return -1L
        }
        return try {
            cm.getConnectionOwnerUid(
                proto,
                InetSocketAddress(srcIP, srcPort.toInt()),
                InetSocketAddress(destIP, destPort.toInt()),
            ).toLong()
        } catch (_: Exception) { -1L }
    }
}
```

### 5. Configuration / Asset Handling

**Asset files inside an AAR need explicit copying**

If your AAR contains `assets/geosite.dat`, you must copy it to `filesDir` yourself. The gomobile bridge does NOT copy assets automatically. Pattern:

```kotlin
fun copyGeoAssets(ctx: Context, destDir: String) {
    val dir = File(destDir)
    if (!dir.exists()) dir.mkdirs()
    for (name in GEO_ASSETS) {
        val dest = File(dir, name)
        if (dest.exists()) continue                    // skip if cached
        try {
            ctx.assets.open(name).use { input ->
                FileOutputStream(dest).use { output -> input.copyTo(output) }
            }
        } catch (e: Exception) {
            Log.w(TAG, "failed to copy asset $name: ${e.message}")
        }
    }
}
```

Then call this before `initCoreEnv(envPath, key)`.

**Template caching**

`context.assets.open(...).readText()` on every config build is wasteful. Cache the parsed template at the object level:

```kotlin
@Volatile
private var templateCache: String? = null

fun build(context: Context, ...): String {
    val template = templateCache ?: context.assets.open("template.json")
        .bufferedReader().use { it.readText() }
        .also { templateCache = it }
    ...
}
```

### 6. Service / Process Lifecycle

**`stopSelf()` BEFORE `closeTun()`, but AFTER `stopForeground`**

Pattern from xray-style services that boot a real engine on a TUN file descriptor:

```kotlin
fun stopAllService() {
    if (!isRunning) return                    // re-entry guard
    isRunning = false
    connectivity.unregisterNetworkCallback(cb)
    coreController?.stopLoop()
    coreController = null
    Seq.setContext(applicationContext)
    stopForeground(true)                    // remove notification immediately
    stopSelf()                               // tell system we'll die
    Thread.sleep(100)                        // let async core actually finish
    closeTun()                               // then close fd
}
```

The `Thread.sleep(100)` comment in the Android lib source is preserved verbatim — it prevents a port-in-use race on quick restart. Don't remove it.

**VPN permission via `ActivityResultLauncher`**

```kotlin
private val vpnPermLauncher: ActivityResultLauncher<Intent> =
    (activity as androidx.activity.ComponentActivity)
        .registerForActivityResult(ActivityResultContracts.StartActivityForResult()) { result ->
            val pending = pendingStart ?: return@registerForActivityResult
            pendingStart = null
            if (result.resultCode != Activity.RESULT_OK) pending.invoke.reject("VPN permission denied")
            else doLaunch(pending)
        }

@Command
fun startCore(invoke: Invoke) {
    val pending = try { resolvePending(invoke) } catch (e: Exception) {
        invoke.reject(e.message ?: "invalid params"); return
    }
    when (val prepareIntent = VpnService.prepare(activity)) {
        null -> doLaunch(pending)
        else -> {
            pendingStart = pending
            vpnPermLauncher.launch(prepareIntent)
        }
    }
}
```

**Prevent self-loop on the TUN**

Always exclude the host package from VPN capture — even for `ALLOW` whitelist mode, since `addAllowedApplication(...)` semantics excludes the host implicitly:

```kotlin
when (appMode.uppercase()) {
    "ALLOW" -> allowedApps.toMutableSet().also { it.remove(packageName) }
        .takeIf { it.isNotEmpty() }
        ?.forEach { safeAllow(builder, it) }
        ?: safeDisallow(builder, packageName)
    else -> safeDisallow(builder, packageName)
}
```

### 7. Proxy / VNService detail (when your AAR requires TUN)

The AAR's underlying xray-core runs entirely on a TUN fd. You MUST:

1. Build TUN via `VpnService.Builder().establish()` and pass the fd to `startLoop(config, fd)`.
2. In the routing config, include a `tun` inbound with `protocol: "tun"`, otherwise the fd has nothing reading it.
3. When `enableFakeDns`, add this rule to the routing config so DNS queries from TUN are routed to the `dns-out` outbound:
   ```json
   {"type":"field","inboundTag":["tun"],"outboundTag":"dns-out","port":"53"}
   ```
   Without it, FakeDNS returns fake IPs but no traffic is captured.

### 8. Configuration JSON Template

Embed a minimal `assets/v2ray_config.json` template in your AAR referencing only the bare essentials:

```json
{
  "log": {"loglevel": "warning"},
  "inbounds": [
    {"tag": "socks", "port": 10808, "listen": "127.0.0.1", "protocol": "socks",
     "settings": {"auth": "noauth", "udp": true},
     "sniffing": {"enabled": true, "destOverride": ["http", "tls"], "routeOnly": false}},
    {"tag": "tun", "protocol": "tun", "settings": {"mtu": 1500},
     "sniffing": {"enabled": true, "destOverride": ["http", "tls"], "routeOnly": false}}
  ],
  "outbounds": [
    {"tag": "proxy", "protocol": "vmess", "settings": {}},
    {"tag": "direct", "protocol": "freedom", "settings": {}},
    {"tag": "block", "protocol": "blackhole", "settings": {"response": {"type": "http"}}}
  ],
  "routing": {"domainStrategy": "IPIfNonMatch", "rules": []},
  "dns": {"servers": ["1.1.1.1", "8.8.8.8"]}
}
```

At runtime, mutate it via `org.json.JSONObject`: replace `proxy` outbound, fill inbounds (port/MTU/sniffing), append DNS, prepend bypass rules. Then `toString(2)`.

## Verification Checklist

Before considering a Tauri Android plugin done, verify each item:

- [ ] `cargo check` clean on host App with `use tauri_plugin_xray::init();`
- [ ] `tauri-plugin-xray/build.rs` COMMANDS list matches `mobile.rs::run_mobile_plugin("…")` and Kotlin `@Command` function names exactly.
- [ ] All commands listed in `permissions/default.toml` as `allow-<command>`.
- [ ] `AndroidManifest.xml` declares the Service with correct `foregroundServiceType` and an `<intent-filter>` if it's a system service.
- [ ] All required `<uses-permission>` (FOREGROUND_SERVICE etc.) declared.
- [ ] Tested on a real device, not just emulator (VpnService + TUN behaves differently).
- [ ] First-call `initEnv` is idempotent (use `AtomicBoolean`).
- [ ] All `catch (_: Exception)` blocks have actual bodies (even if empty `{}`).
- [ ] Thread-safety: cross-thread mutable state has `@Volatile` or uses `AtomicReference`.
- [ ] No stale `Seq.setContext(VpnService)` reference after the service stops.
- [ ] Resource extraction in `catch` blocks doesn't leak (or use `use {}`).
- [ ] Permission denied path is handled — show user-facing error rather than crashing.
- [ ] Test with both `config` raw JSON and `nodeUri` paths if your plugin builds configs.

## Reference Implementations

When implementing another Tauri plugin that wraps a native lib, study these
public repositories (clone them locally rather than assuming any fixed path):

- Your own previous plugin's `android/src/main/kotlin/<pkg>/` and `src/` —
  the full plugin layout, including the dual mobile/desktop split.
- [v2rayNG](https://github.com/2dust/v2rayNG) (`V2rayNG/app/src/main/java/com/v2ray/ang/`) — battle-tested VPN/service patterns:
  - `service/CoreVpnService.kt` — VPN/service lifecycle
  - `service/CoreRootService.kt` — non-VPN service variant
  - `core/CoreServiceManager.kt` — core start/stop orchestration
  - `core/CoreConfigManager.kt` / `core/CoreOutboundBuilder.kt` — configuration builder pattern
- [AndroidLibXrayLite](https://github.com/2dust/AndroidLibXrayLite) — the
  gomobile source pattern for building an Xray-core AAR.
